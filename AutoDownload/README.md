# Auto Download

按会话、按网络类型自动下载媒体文件。

## 能做什么

- **按媒体类型选择**：图片、视频、GIF、语音/音频、文件，各自独立开关
- **按网络环境分开设**：WiFi 一套规则，移动数据另一套规则
- **按会话单独设**：给频道 A 设"WiFi 下自动下载图片和视频"，给群组 B 设"只下图片"
- **默认规则兜底**：没单独配置的会话按默认规则走
- **自定义优先**：会话一旦配置过，就以会话自己的设置为准，不再看默认规则
- **只管已开启的会话**：某个会话被显式禁用后，该会话完全不自动下载

## 怎么用

### 1. 配置默认规则

插件设置 → **默认规则** → 分别进「WiFi 下自动下载」和「移动数据下自动下载」勾选类型。
这里只影响**没有单独配置过**的会话。

### 2. 给某个频道/群组单独配置

在频道或群组里 → 右上角菜单 → **自动下载设置** → 三选一：

| 选项 | 效果 |
|---|---|
| 启用自动下载 | 把该会话加入配置列表，规则初值沿用当前默认规则 |
| 禁用自动下载 | 保留配置，但该会话不自动下载任何媒体 |
| 移除该会话配置 | 删除配置，回到默认规则 |

加进去之后，到插件设置 → **已配置的会话** → 点该会话 → 分别勾选 WiFi 与移动数据下要下哪些类型。

频道/群组与个人资料页都有这个菜单项。

### 3. 作用范围

插件设置 → **默认作用范围**：

- **所有会话（可逐个关闭）**——默认。所有会话先按默认规则来，你可以逐个关掉不想要的
- **仅已添加的会话**——只有手动加进列表的会话才启用，其余完全不管

## 默认规则初值

| | 图片 | 视频 | GIF | 语音/音频 | 文件 |
|---|---|---|---|---|---|
| WiFi | ✔ | ✔ | ✔ | ✔ | ✘ |
| 移动数据 | ✔ | ✘ | ✘ | ✘ | ✘ |

移动数据下默认只下图片，避免偷跑流量。

## 安装

1. exteraGram → 设置 → 插件 → 打开**插件引擎**；插件信息页打开**开发者模式**
2. 把 `auto_download.plugin` 复制进设备的插件目录，**并改名为 `auto_download.py`**
3. 在插件列表里启用，重启应用

> 关于后缀：`.plugin` 是**源码后缀**（仓库里存的就是它，没有构建步骤）；
> 设备上加载器只认 `.py`，所以推上去时要改名。文件名还必须和插件 id 一致。

用 adb 推（注意第一行就完成了改名）：

```bash
adb push auto_download.plugin /data/local/tmp/auto_download.py
adb shell "su -c 'cp /data/local/tmp/auto_download.py /data/data/com.exteragram.messenger/files/plugins/auto_download.py'"
adb shell "su -c 'chown <uid>:<uid> /data/data/com.exteragram.messenger/files/plugins/auto_download.py'"
adb shell "su -c 'chmod 600 /data/data/com.exteragram.messenger/files/plugins/auto_download.py'"
adb shell "am force-stop com.exteragram.messenger"
```

`<uid>` 换成应用的 uid（`adb shell "su -c 'stat -c %u /data/data/com.exteragram.messenger'"`）。

## 前置条件

- exteraGram **12.5.1 以上**
- 插件 SDK **1.4.5.0 以上**
- **应用自身的自动下载总开关要打开**。本插件改的是"这条媒体此刻要不要下"的判断，
  不是在应用总开关关闭的情况下强行下载。

## 不生效怎么办

1. 插件设置 → **运行自检**。自检结果会**写成文件**：插件目录下的
   `auto_download_report.txt`（用任意 root 文件管理器打开）。抓不到 logcat 时看它
2. 能连 adb 的话：`adb logcat -s plugin.auto_download`，重点看开头的"宿主能力"那行
3. 还不行就装 `tools/autodl_probe.plugin`，按 `docs.md` 的「真机验证步骤」拉报告

常见问题：

| 现象 | 原因 |
|---|---|
| 完全没反应 | 挂点没挂上（版本差异）；或应用自身全局自动下载关着。看自检报告里的「已挂钩重载数」 |
| 该下的没下 | 应用全局自动下载关着；或会话被显式禁用了；或移动数据规则没勾 |
| 不该下的下了 | 宿主常量语义与本插件假设相反，把「允许返回值（兼容）」改成固定值再试 |
| 设置页里会话名是空白 | 该会话还没进过配置流程，重新从菜单加一次 |

## 风险

- 移动数据下自动下载会**消耗流量**。改规则前先看清楚当前是 WiFi 还是移动数据
- 未知网络类型（以太网、部分 VPN）按**移动数据**处理，即按更保守的规则执行
- 本插件依赖宿主内部方法名，应用大版本更新后可能失效；失效时不会崩溃，只是不生效
- 贴纸、联系人、位置不干预，交给应用自己处理
