# 消息过滤规则编写

把一句自然语言需求变成 **Message Filter 插件里能直接填的规则**。

插件的规则模型（字段名就是设置页上显示的名字，必须原样对上）：

| 字段 | 可填值 |
|---|---|
| 类型 | `词组 / 子串` · `字符集合` · `正则表达式` |
| 匹配内容 | 按类型填（见下） |
| 替换为 | 纯文本；**留空 = 直接删掉** |
| 区分大小写 | 开 / 关 |
| 作用方向 | `仅收到的消息` · `仅发出的消息` · `收 + 发` |
| 作用范围 | 全局（插件设置里加）或 仅某个会话（在那个群/频道的右上角菜单里加） |
| 优先级 | 列表顺序，越靠前越先执行 |

## 一、工作流：需求 → 规则

**不要一上来就写正则。** 按这 5 步走，能避免绝大多数误伤。

### 第 1 步：定目标形态

问自己：要删的东西是**哪一类**？

| 形态 | 例子 | 该用 |
|---|---|---|
| 固定不变的文字 | `加微信`、`转发自某某` | **词组** |
| 一堆无规律的单个字符 | `★☆●◆※`、零宽字符 | **字符集合** |
| 有结构、有边界、有可选部分 | 手机号、链接、整行广告 | **正则** |

**能词组就别正则** —— 词组模式最快、最不可能误伤。

### 第 2 步：定边界

正则最容易翻车的地方是"到哪结束"。先明确终点，再选写法：

| 终点 | 写法 |
|---|---|
| 到行尾 | `[^\n]*` 或 `.*`（`.*` 默认不含换行） |
| 到空格/标点 | `[^\s，。！？]*` |
| 到某个字之前 | 用**后顾**做不到（Python `re` 支持 `(?<=)` 但不支持变长后顾），改用 `re.sub` 思路：把前缀一起匹配进去 |
| 固定长度 | `\d{11}` |

### 第 3 步：选模式并写出 pattern

见第二节的映射表。

### 第 4 步：跑反例（必做）

拿 **3 条不该被过滤的正常消息**，逐条心算一遍 pattern 是否匹配。
匹配上了就说明写太宽，回去收紧。这一步是唯一能防误伤的环节。

### 第 5 步：设保险

- pattern 可能匹配整条 → 把插件设置里的 **「过滤后为空」改成 `放弃修改（保留原文）`**
- 拿不准时先在 **「记录过滤记录」** 打开的状态下试，能看到命中前/后对比

## 二、常见需求 → 现成规则

### 删整行后留下空行怎么办

`(?m)^…$` 里的 `$` 是**零宽断言**，只匹配到换行**之前**——所以匹配到的内容**不含那个 `\n`**。
文字删了、换行还在 ⇒ 原地留下一个空行。

```
原: 正常消息\n广告行\n正常消息二
删: 正常消息\n<空>\n正常消息二      ← 广告行没了，但那个 \n 还在
```

**修法：在模式末尾补一个 `\n?`**，把整行连同它的换行一起吃进去：

```
(?m)^…[^\n]*\n?      ← 整行 + 换行
(?m)^…[^\n]*$        ← 只到换行前（会留空行）
```

补了 `\n?` 之后**不需要**动「链接安全（等长隐身删除）」：那个 `\n` 会被换成一个零宽空格，
总长度仍然一字不差 ⇒ offset 依旧有效 ⇒ 链接照样不会串位，而且**相邻行也不会黏连**
（上一行自己的换行没被碰）。实测同一条消息：不补 `\n?` 留 4 个空行，补了只剩 1 个（末尾那个隐形的）。

下面凡是"删整行"的规则都已经带 `\n?`。

### 广告 / 引流

| 需求 | 类型 | 匹配内容 |
|---|---|---|
| **去掉奖牌推广行（含榜单行、原「emoji 排行榜行」）** | 正则 | `(?m)^[^\S\n]{0,3}(?:[\U0001F947-\U0001F949\U0001F396]\uFE0F?[^\n]*\n?\|(?!.*(?<![A-Za-z0-9\u4e00-\u9fff])[0-9]{1,4}[kK][^\S\n]*$)[\U0001F300-\U0001FAFF\u2600-\u27BF\u2B00-\u2BFF\u2190-\u21FF]\uFE0F?[^\n]*?(?:上门\|包养\|约炮\|定制\|直营\|放心约\|首单免\|介绍费\|不嫩不要钱\|无定金)[^\n]*\n?)` |
| 去掉含奖牌 emoji 的整行（不限行首） | 正则 | `(?m)^.*?[\U0001F947-\U0001F949\U0001F396].*\n?` |
| 只删掉奖牌 emoji 本身（不管在哪，保留其余文字） | 正则 | `[\U0001F947-\U0001F949\U0001F396]\uFE0F?` |
| 去掉"加微信"三个字 | 词组 | `加微信` |
| 去掉各种加好友话术 | 正则 | `(?:加\|＋)\s*(?:微\|v\|V\|威\|薇)\s*[信心]?\s*[:：]?\s*[A-Za-z0-9_-]{4,}` |
| 去掉整行广告（含关键词就删整行） | 正则 | `(?m)^.*(?:加微\|加V\|推广\|优惠\|代购\|返利).*\n?` |
| 去掉"转发自 xxx" | 正则 | `转发自\s*\S+` |
| 去掉手机号 | 正则 | `1[3-9]\d{9}` |
| 去掉 QQ 号 | 正则 | `[Qq]{2}\s*[:：]?\s*\d{5,12}` |
| 去掉邮箱 | 正则 | `[\w.+-]+@[\w-]+\.[\w.]+` |
| 去掉 t.me 链接 | 正则 | `(?:https?://)?t\.me/\S+` |
| 去掉任意链接 | 正则 | `https?://\S+` |
| 去掉 @提及 | 正则 | `@[A-Za-z0-9_]{3,32}` |
| 去掉价格/促销标签 | 正则 | `[【\[].{0,12}(?:特价\|秒杀\|限时).{0,12}[】\]]` |

#### 上面那条「奖牌推广行」怎么用（一条顶两条）

它是**两条判据合成的一条规则**，靠 `(?:A|B)` 分两支：

| 分支 | 判据 | 例子 |
|---|---|---|
| A（奖牌行） | **行首是奖牌 emoji** 🥇🥈🥉🎖 —— 唯一且最可靠，不靠词袋猜 | `🥈【萝莉全国包养】…`、`🎖️m官方直营放心约…` |
| B（emoji+推广词） | 行首是任意 emoji，**且**行内出现强推广词，**且**行尾没有「数字k」价目 | `🔥上门服务 仅需88`、`💸包养 直营 无定金` |

要点：

- `[^\S\n]{0,3}`：行首最多 3 个空白；用 `[^\S\n]` 而不是 `\s`，避免把换行也吃进去
- `\uFE0F?`：兼容 🎖️ 这种带变体选择符的写法
- `(?!.*…[0-9]{1,4}[kK][^\S\n]*$)`：**价目闸门**。`📢广州茶馆 159k`、`👍这个我出 5k` 这类一律放过
- 判据是"行首 emoji"，所以 `热搜：…` 索引行、`👇点击按钮…` 导航行、行中间的奖牌都不会被误伤
- 想连 ⭐🌟 开头的行也无条件删？把分支 A 的字符类改成 `[\U0001F947-\U0001F949\U0001F396\u2B50\U0001F31F]` 即可 —— 但**普通星标消息也会被删**，不建议

#### 为什么"奖牌明明在，却没匹配上"

先记住：**奖牌必须在行首**，这是分支 A 的判据本身。逐条对照：

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 奖牌在行中间，如 `abc 🎖🥉🥇` | 分支 A 要求 `^` 行首就是奖牌，行中间的不算 | 用上面那条「去掉**含**奖牌 emoji 的整行」，或「只删掉奖牌本身」 |
| 消息里有 🏅（U+1F3C5 运动奖牌） | 字符集只有 🥇🥈🥉🎖，**🏅 不在里面** | 字符类里补 `\U0001F3C5`，或改用「含奖牌的整行」那条 |
| 奖牌前有 4 个以上空格/制表符 | `[^\S\n]{0,3}` 只放行 ≤3 个空白 | 改成 `[^\S\n]*`（不限缩进） |
| 奖牌前有零宽字符（U+200B/200C/FEFF） | 那是**不可见**字符，眼睛看着在行首，其实不是 | 先加一条字符集合规则删零宽字符，或把 `[^\S\n]{0,3}` 换成 `[\s\u200b\u200c\u200d\ufeff]{0,4}` |
| 奖牌是图片/贴纸，不是文字 | 插件只处理**文本** | 无解 |
| 规则一点没反应 | 作用方向默认是**仅收到的消息**，自己发出去的消息不处理 | 把方向改成「收 + 发」 |
| 聊天里已经有这条消息，改完规则它没变 | 已显示的气泡**不会回溯重算** | 让**对方**新发一条再看 |
| 刚加的规则立刻测 | 配置有 **3 秒缓存** | 等 3 秒，或退出重进设置页 |
| 在群里从右上角菜单加的规则，却去别的聊天测 | 那条规则**只绑定那个会话** | 在那个群里测，或在插件设置里加全局规则 |
| 粘到在线正则工具里试 | 在线工具是 JS/PCRE，`\U0001F947` 这种 8 位写法**只有 Python 认** | 认准插件里类型是「正则表达式」；在线验证请选 Python `re` |
| 类型选成了「词组 / 子串」 | 词组模式不认正则，整串会被当普通文字 | 类型改成「正则表达式」 |


### 搜索 bot 结果清理

搜索类 bot 的一条消息里会混三类行：**奖牌开头的推广行**、**结果行**（🏞🎬📄 开头，带 t.me 链接）、**热搜等索引行**。要"只留干净结果"，有两条路子：

| 需求 | 类型 | 匹配内容 |
|---|---|---|
| 搜索 bot：只删奖牌行 + 热搜行（保留其余结果） | 正则 | `(?m)^[^\S\n]{0,3}(?:[\U0001F947-\U0001F949\U0001F396]\uFE0F?[^\n]*\n?\|热搜[^\n]*\n?)` |
| 搜索 bot：只保留结果行（🏞🎬📄 开头），其余全删 | 正则 | `(?m)^[^\S\n]*(?![\U0001F3DE\U0001F3AC\U0001F4C4])[^\n]*\n?` |

两条都带 `\n?`（连换行一起删），所以**不会留下空行**。见上面「删整行后留下空行怎么办」。

怎么选：

- **删法（第一条，推荐）**：只动你点名的那两类，结果行一个不碰。bot 以后加了别的行也不会被误删。
- **留法（第二条，更彻底）**：除 🏞🎬📄 开头的一律删，连 bot 底部广告、导航行一起清掉。代价是**结果行的 emoji 一改就会全删光**——换 bot 或 bot 改版后要重新确认这三个 emoji。

> ⚠️ **别用带「emoji + 强推广词」分支的整合规则来清搜索 bot 结果。**
> 实测：结果行 `🎬[14:59] 【19岁_爆乳大学生_林恩琪_遭土豪包养_3P视频曝光…` 里含"包养"，
> 会被那个分支当成推广行**整行删掉** —— 而它是你要的结果。
> 清理搜索 bot 请用上面这两条窄规则。

### 装饰 / 格式垃圾

| 需求 | 类型 | 匹配内容 |
|---|---|---|
| 去掉一堆装饰符号 | 字符集合 | `★☆●◆▪▫◦※✿❀¤§¶` |
| 去掉零宽字符（隐形水印） | 字符集合 | `\u200b\u200c\u200d\ufeff`（字符集合模式下 `\u` 写法**不生效**，见第三节坑 2） |
| 去掉行尾的 emoji 尾巴 | 正则 | `[\U0001F300-\U0001FAFF\u2600-\u27BF]+$` |
| 去掉重复刷屏字符 | 正则 | `(.)\1{9,}` |
| 去掉首尾空白 | 正则 | `^\s+\|\s+$` |

> 原来的「去掉 emoji 排行榜行」已升级成上面那条**完整的奖牌推广行规则**（见「广告 / 引流」）——
> 旧写法 `(?m)^\s*[🥇🥈🥉🎖⭐🌟]\uFE0F?.*` 有两个毛病：`\s*` 会把换行也吃进去，
> 而且无条件删掉 ⭐🌟 开头的**正常**星标消息。

### 内容屏蔽

| 需求 | 类型 | 匹配内容 |
|---|---|---|
| 屏蔽某几个词 | 词组 | 一个词一条规则（**不要**用 `\|` 拼，词组模式不认正则） |
| 屏蔽一批同义写法 | 正则 | `(?:关键词1\|关键词2\|关键词3)` |
| 屏蔽脏话（避免匹配到正常词） | 正则 | 用 `\b` 或前后字词限定，别裸写 |

## 三、四条硬规矩（插件实现决定的，写错了必然没用）

### 1. 「替换为」是纯文本，**不支持 `\1` 反向引用，也插不进换行**

插件是手工拼接替换结果的，替换文本会**原样**写进消息：

- `\1`、`\g<1>` → 输出字面的 `\1`，不是捕获组
- `\n` → 输出字面的反斜杠 + n，**不是换行**（该输入框是单行）

所以"保留一个字符、删掉其余"「把连续空行压成一个空行」这类需求**做不到**，
只能整段删掉，或者用一个固定字符串整体替换。遇到这种需求要**主动告诉用户做不到**，
不要给出一个看起来能用的 `\1` 规则。

### 2. 字符集合模式里 `pattern` 是**字面字符表**，不是正则

- `\d` 会被理解成「反斜杠」和「字母 d」两个字符，只删这两种
- 想删数字请用**正则模式**写 `\d`
- 想删 `\u200b` 这类不可见字符，字符集合模式做不到 → 改用**正则模式**写 `[\u200b\u200c\u200d\ufeff]`

### 3. 词组模式也不是正则

`.*`、`(a|b)` 在词组模式里就是普通文字，只会去匹配这些字面字符。
要用通配/选择就切到**正则模式**。

### 4. 正则语法是 **Python `re`**，不是 PCRE / JS

| 写法 | 结果 |
|---|---|
| `\x{FE0F}` | ❌ PCRE / Rust 写法，Python 报 `bad escape` |
| `\uFE0F` | ✅ Python 写法 |
| `(?m)` | ✅ 多行模式，`^` `$` 匹配每行 |
| `(?<=abc)` | ✅ 定长后顾 |
| `(?<=a{1,3})` | ❌ 变长后顾，Python 不支持 |
| `(?s)` | ✅ 让 `.` 也匹配换行 |

写错的正则不会让插件崩：`运行自检` 和规则列表的副标题会显示 `无效: …`。

## 四、输出格式（照这个给用户）

每条规则给一张这样的表，用户可以直接照抄进设置页：

```
规则名：去广告尾巴
类型：正则表达式
匹配内容：(?m)^.*(?:加微|推广|优惠).*$
替换为：（留空）
区分大小写：关
作用方向：收 + 发
作用范围：全局
```

然后补三句话：

1. **优先级**：多条规则按上面的顺序填（越靠前越先执行）
2. **保险**：如果这条可能匹配整条消息，把「过滤后为空」改成 `放弃修改`
3. **反例**：列出你验过的 3 条正常消息，说明它们不会被误伤

### 只在某个群/频道生效

如果用户说「**只在这个群**过滤」，不要说"改成仅某会话"就完事 —— 具体操作是：

> 进那个群/频道 → 右上角菜单 → **消息过滤规则** → **＋ 添加规则（仅本会话）** → 填「匹配内容」→ 添加

从菜单加的规则**自动绑定当前会话**，不会全局生效；插件设置页里每条规则会显示自己的作用范围。

## 五、排错对照

| 现象 | 原因 |
|---|---|
| 规则一点没生效 | 规则被禁用；或作用方向选了「仅发出」却在看收到的消息 |
| 只在某个群不生效 | 那条是**全局**规则？还是作用方向不对？在插件设置里看规则的副标题 |
| 显示 `无效: …` | 正则语法错，看副标题里的原文（常见：`\x{}` 写法、括号不配对） |
| 改了设置没反应 | 配置有 3 秒缓存；**已经显示在屏幕上的消息不会回溯重算** |
| 消息整条变成 `（已过滤）` | pattern 匹配到全文了；收紧 pattern，或把「过滤后为空」改成 `放弃修改` |
| 格式（加粗/链接）错位 | 把「同步修正加粗/链接偏移」保持开启 |
| 词被删了一半 / 删多了 | 正则没定好边界，加 `\b` 或用 `(?m)^…$` 限定成整行 |

## 六、自检清单

给用户规则之前，逐条过一遍：

```
[ ] 类型选对了？（能词组就别正则）
[ ] pattern 里没有 \1 之类反向引用（替换为不支持）
[ ] 字符集合模式里没写 \d \u 这类转义
[ ] 正则用的是 Python re 语法，不是 \x{...}
[ ] 作用方向对不对？（默认是「仅收到的消息」）
[ ] 该全局还是该在群里从菜单加？
[ ] 3 条反例都验过不误伤？
[ ] 可能匹配整条时，提示了「过滤后为空」的保险设置
```
