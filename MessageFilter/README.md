# Message Filter

按自定义规则**移除消息里匹配的部分**，保留消息其余内容——不是删除整条消息。

## 能做什么

- **三种匹配方式**：词组/子串、**字符集合**（逐字符删）、**正则表达式**
- **只删匹配的部分**：`今天促销 加微信xxx 速来` → `今天促销  速来`
- **也可以替换**：把 `12345` 换成 `****`，而不只是删掉
- **多条规则按优先级顺序执行**：列表越靠前越先执行
- **逐条启用/禁用**：临时关掉某条规则，不用删
- **分方向生效**：只过滤收到的、只过滤发出的、或都过滤
- **给处理过的消息加标记**：默认 `🚫`，可改成任意文字/emoji，可放开头或末尾
- **格式不串味**：改写文本后自动修正加粗/链接的偏移；拿不到格式实体时改用
  「等长隐身删除」，保证链接不会串到别的行
- **可以只在某个群/频道生效**：在那个群的右上角菜单里直接加规则，不会影响别的聊天
- **历史消息也过滤**：不只管新来的，打开会话/翻历史/搜索时同样生效

## 怎么用

### 1. 添加规则

插件设置 → **添加规则** → 在「匹配内容」里填 → 选类型 → 点**添加这条规则**。

| 类型 | 填什么 | 例子 |
|---|---|---|
| 词组 / 子串 | 要删的整段文字 | `加微信` → 删掉所有"加微信" |
| 字符集合 | 一堆字符 | `★☆●` → 删掉消息里出现的所有 ★、☆、● |
| 正则表达式 | Python `re` 语法 | `\d{6,}` → 删掉 6 位以上的数字串 |

### 2. 调细节

在**规则**列表里点进某条规则：

| 项 | 说明 |
|---|---|
| 启用这条规则 | 临时关掉这条，其它规则照常 |
| 类型 | 词组 / 字符集合 / 正则 |
| 匹配内容 | 规则本体 |
| 替换为 | 留空 = 直接删掉；填了就把匹配部分换成它 |
| 区分大小写 | 默认开 |
| 作用方向 | 仅收到的 / 仅发出的 / 收 + 发 |
| 上移 / 下移 | 调整优先级 |
| 删除这条规则 | — |

规则不合法（比如正则写错）时，该规则会被跳过，并在列表的副标题上显示原因。

> 「替换为」是**纯文本**：不支持 `\1` 反向引用，也插不进换行。
> 所以"保留一个字符、删掉其余"这类需求做不到，只能整段删或整体换成一个固定文本。

### 3. 只在某个群 / 频道生效（快捷方式）

不想全局生效的话，**不用进插件设置**：

1. 打开那个群或频道（频道也支持点资料页）
2. **右上角菜单 → 消息过滤规则**
3. 点 **＋ 添加规则（仅本会话）** → 填「匹配内容」→ 添加

从菜单加的规则**只在这个会话生效**，自动绑定当前会话，别的聊天完全不受影响。

同一个菜单里还能看到这个会话已有的规则，点一条可以：

| 操作 | 说明 |
|---|---|
| 启用 / 禁用 | 临时关掉，不用删 |
| 删除 | 彻底移除 |

规则列表里每条后面会标出它的作用范围（`全局` 或 `仅「某群」`）。
想把某条会话规则改成全局，进插件设置 → 点开那条规则 → **改为全局（所有会话）**。

> 插件设置里加的是**全局规则**；群菜单里加的是**会话规则**。
> 全局规则永远排在会话规则前面执行（先做通用清理，再跑专属规则）。

### 4. 过滤后的标记

插件设置 → **过滤后的标记**：

- 开关关掉 → 处理过的消息看不出区别
- 标记内容 → 默认 `🚫`，可以改成 `[已过滤]` 之类
- 标记位置 → 开头 / 末尾

**整条消息都被删空时**，在**边界情况 → 过滤后为空**里选：

| 选项 | 效果 |
|---|---|
| 用占位文本（默认） | 变成 `（已过滤）` |
| 留空 | 消息变空 |
| 放弃修改（保留原文） | **最保守**，宁可不改 |

### 5. 两个边界开关

| 开关 | 默认 | 说明 |
|---|---|---|
| 同步修正加粗/链接偏移 | 开 | 改写文本后自动修正格式实体的坐标 |
| 链接安全（等长隐身删除） | 开 | 拿不到格式实体时，把被删字符换成等宽**零宽字符**，保证总长度不变、链接不串位 |

为什么要「等长隐身」：有些版本里可跳转的链接挂在宿主自己的对象上，插件碰不到，
直接删字会让后面所有链接的坐标失效——表现就是**第一行的链接跑到第二行去了**。
这时改成"原地换成看不见的字符"，长度一字不差，链接就不可能串位。
代价是被删的位置会留下不可见的零宽字符，想要文本绝对干净可以把它关掉。

> 开着「链接安全」时，标记会**固定加在末尾**（加开头会让整体坐标平移）。

## 安装

1. exteraGram → 设置 → 插件 → 打开**插件引擎**；插件信息页打开**开发者模式**
2. 把 `message_filter.plugin` 复制进设备的插件目录，**并改名为 `message_filter.py`**
3. 在插件列表里启用，**重启应用**

> `.plugin` 是**源码后缀**（仓库里存的就是它，没有构建步骤）；设备上加载器只认
> `.py`，所以推上去时要改名。文件名还必须和插件 id 一致。

用 adb 推（第一行就完成了改名）：

```bash
adb push message_filter.plugin /data/local/tmp/message_filter.py
adb shell "su -c 'cp /data/local/tmp/message_filter.py /data/data/com.exteragram.messenger/files/plugins/message_filter.py'"
adb shell "su -c 'chown <uid>:<uid> /data/data/com.exteragram.messenger/files/plugins/message_filter.py'"
adb shell "su -c 'chmod 600 /data/data/com.exteragram.messenger/files/plugins/message_filter.py'"
adb shell "su -c 'rm -f /data/data/com.exteragram.messenger/files/plugins/__pycache__/message_filter.cpython-311.pyc'"
adb shell "am force-stop com.exteragram.messenger"
```

`<uid>` 换成应用的 uid（`adb shell "su -c 'stat -c %u /data/data/com.exteragram.messenger'"`）。

## 前置条件

- exteraGram **12.5.1 以上**
- 插件 SDK **1.4.5.0 以上**

## 不生效怎么办

按顺序试，三步基本能定位：

1. 插件设置 → **诊断 → 运行自检**：会弹「规则 N 条，启用 M 条」，并把
   「规则清单 + 链接安全状态 + 已见会话键」写进设置页（`_self_check`）。
   如果「已见会话键」一直是空的，说明**钩子根本没收到消息**，问题在宿主侧。
2. 打开**诊断 → 只观察不改（样本捕获）**，然后收一条消息，回到
   **过滤记录**页看「最近处理」：有样本行 = 钩子在跑、规则也命中了；
   没动静 = 规则没命中，去看规则的作用范围与方向。
3. 打开**记录过滤记录**，到**过滤记录**里看每条的「原文 ⇒ 结果」。

也可以用 `adb logcat -s plugin.message_filter` 看日志，`[过滤]` 开头的行
就是命中记录，`已注册 N/M 个钩子` 会告诉你哪条钩子没挂上。

常见问题：

| 现象 | 原因 |
|---|---|
| 一条都没过滤 | 规则没启用；或作用方向选了「仅发出」却在看收到的消息 |
| 只在某个群不生效 | 那条其实是**全局**规则？它是不是被别的规则抢先处理了？在插件设置里看它的作用范围 |
| 群里加的规则完全没反应 | v1.1.0 已修「会话键写法不一致」这个坑；确认插件版本 ≥ 1.1.0 |
| 别的群也被过滤了 | 那条是全局规则。想在单个群生效，请从那个群的右上角菜单里加 |
| 菜单里点「添加规则」没反应 | 拿不到界面上下文；改用插件设置页添加 |
| 设置里改了规则，消息没变 | 配置有 3 秒缓存；已经显示在屏幕上的气泡不会回溯重算 |
| 过滤后文字怪怪的 | 关掉「同步修正加粗/链接偏移」试试；一般是格式实体换算问题 |
| 删掉的地方还能选中/复制出空白 | 那是「链接安全」留下的零宽字符；不需要保链接就把它关掉 |
| 消息整条变成占位文本 | 规则匹配到了全文；把「过滤后为空」改成「放弃修改」 |
| 加了标记但没看到 | 「给处理过的消息加标记」被关了，或消息其实没被改动 |

## 风险

- **本插件只改你自己客户端上显示的消息文本**，不改服务端数据，也不改别人的客户端
- 过滤发生在**消息到达那一刻**；已经显示出来的气泡不会因为改设置而重算
- 规则写得太猛（比如正则 `.*`）会把消息清空，建议先用「放弃修改」选项试
- 「颜色标记」未实现，目前只有文本/emoji 标记
- 「替换为」是纯文本，不支持 `\1` 反向引用，也插不进换行
- 「链接安全」开启时，被删位置会留下不可见的零宽字符 U+200B
- 会话规则作用在**收到的消息**上最可靠；发出的消息能否按会话过滤，取决于宿主
  是否把会话信息一起交给钩子（没带就只应用全局规则）
